# Maritime Chat-Law

Maritime Chat-Law 是面向海事合同争议的多智能体共识系统，结合海事微调语言模型与 LangGraph，组织不同角色围绕案件事实、合同解释、责任归属和救济请求进行分析与交互。

系统以结构化案例和十个争点为输入，由五个智能体分别形成初始意见，再通过讨论、回应与观点更新记录共识的演化过程。五个角色包括一名中立技术鉴定人、两名船厂代理律师和两名船东代理律师；它们共用同一微调模型服务，但各自维护独立的身份和意见状态。

## 共识机制

- **投票共识**：根据各争点的二元立场计算一致性，通过多边讨论和中央调解形成候选方案，再由各智能体独立决定如何更新意见。
- **语义共识**：对完整意见生成摘要，利用模型进行双向两两评分，选择对称相似度最低的一对开展双边交互，并将交互内容反馈给其他成员。

## 源文件说明

两种共识机制分别由独立的主文件实现，公共模块提供提示词、模型接口、状态管理和指标计算。

| 文件 | 主要内容 |
|---|---|
| `voting_consensus.py` | 投票机制主文件，定义二元共识测量、多边发言、中央调解、意见更新及最终建议的流程。 |
| `semantic_consensus.py` | 语义机制主文件，定义摘要生成、双向语义评分、最低相似度配对、双边交互及全体反馈的流程。 |
| `run_experiment.py` | 统一组织实验与重复运行，管理初始意见和两条机制的执行，保存逐轮状态并导出统计表。 |
| `verify_results.py` | 根据保存的原始评分与意见复算共识指标，检查输入、交互状态及导出结果之间的一致性。 |
| `shared/prompts.py` | 定义初始分析、意见摘要、语义评分、多边讨论、双边协商、意见修订和最终建议的提示词模板。 |
| `shared/metrics.py` | 实现二元立场一致性、语义评分对称化、成员及群体共识、异常成员识别、均值和标准差计算。 |
| `shared/runtime.py` | 提供模型接口调用、请求与响应记录、公共状态结构、并发处理和输入输出格式校验。 |
| `shared/__init__.py` | 公共模块包入口，用于组织两个机制共享的功能。 |
| `configs/lawllm_vllm.json` | 保存模型服务名称、接口地址、采样参数、交互轮数、相似度阈值、反馈策略及微调权重信息。 |
| `data/case_paper_roles.json` | 保存结构化案例事实、双方主张、合同条款、十个争点及五个智能体的身份设定。 |
| `requirements.txt` | 列出实验程序的主要依赖及版本范围。 |
| `requirements.lock.txt` | 记录实验环境中依赖库的具体版本。 |

## 模型文件

海事微调模型由 `ShengbinYue/LawLLM-7B` 基座与 `checkpoint-2268` LoRA 适配器共同组成。基座模型需另行下载，放入 `models/LawLLM-7B/`；海事 LoRA 权重及配套分词器文件也需从单独的下载渠道获取，放入 `models/checkpoint-2268/`。LoRA 权重必须与基座配合使用，不能独立替代完整基座。

`models/checkpoint-2268/` 应包含以下推理文件：

| 文件 | 主要内容 |
|---|---|
| `adapter_model.safetensors` | 海事微调得到的 LoRA 参数。 |
| `adapter_config.json` | LoRA 结构、秩、缩放参数及适配层配置。 |
| `tokenizer.json` | 分词器词表、合并规则和文本编码处理配置。 |
| `tokenizer_config.json` | 分词器配置及微调模型使用的对话模板。 |
| `special_tokens_map.json` | 特殊标记与分词器属性的映射。 |
| `added_tokens.json` | 新增标记及其编号。 |
| `vocab.json` | 词表中的标记与编号映射。 |
